# PLEの測定・保存仕様（revision 2）

## 測定対象

CONEX位置を走査し、各位置で独立したPLスペクトルを指定回数取得する。繰り返しとLightFieldのframes-combinedは別の値として保存する。任意の多次元レシピエディターはこの版の対象外。

BG→最初のPL→解析条件の確認→残りの走査という順序。最初のPLはpreviewとして直ちに保存し、条件確定まで次の取得を行わない。確定後は同じPLを1点目へ昇格させる。

`PL peak position`と半幅で定義した閉区間の最大countsのビンをPLピークとする。独立した積分min/maxの区間について波長軸上の台形積分を計算する。積分の両端は隣接ビン間の線形補間を使う。ピークはフィットによるサブピクセル推定ではない。生countsではなくBG差し引き後の値を使い、負の値も削除しない。積分単位はcounts·nm。

## 励起波長

PL解析ピークとは独立した設定。

- Spectrum peak：指定区間のBG差し引き後の最大ビン。正の内点であることを要求し、区間境界のピークを成功扱いしない。区間の中央値を基線、1.4826×MADを雑音の指標とし、設定した最小SNR（既定5）以上を要求する。複数ピークや宇宙線の高度な判別は実装していないため、実測スペクトルを確認する。
- Calibration：ユーザー入力の位置・波長対応を区分線形補間する。位置の重複、波長の非単調、校正範囲外の指令位置を禁止。読み戻した位置で換算し、指令位置だけで換算しない。読み戻し位置が校正範囲を外れた場合は、ステージ位置許容差以内に限って端の区間の傾きで外挿し、取得ごとに `analysis.log` へ1行記録する。

Demoの初期校正点は架空の例であり、実機校正ではない。Hardwareへ切り替えたときは設定内容を確認する。

## 波長／エネルギー表示

`E [eV] = 1239.8419843320026 / λ [nm]`。

エネルギー表示は各ビンの横座標を変換し、強度は検出器ビンごとのcountsを保持する。counts/nmやcounts/eVといった密度に変換する処理ではない。パワー正規化時はcountsを試料上推定パワーWで割る。積分指標は表示軸にかかわらず同じ波長区間のcounts·nm。

## BGと元データ

各測定で新しいBGを取得する。遮光・復帰の記録付き手動確認、または[kohdalab-shutter／MFF自動シャッター](shutter.md)を選ぶ。自動方式は終了・中断時に遮光を要求する。状態番号と実光路の対応はユーザー設定であり、機器側の読戻しは光学的遮光を直接測定するものではない。測定とBGの波長配列が一致しない場合は処理を中断し、補間して見かけ上一致させない。LightFieldの露光・frame combined・中心波長・gratingの読戻し値の一致も確認する。ROIや読出し方式などベンダーの詳細条件はSPEに保持されるが、この版で全設定の適合性を網羅していない。

Raw SPEとLightFieldのエクスポートは取得時のまま保持する。共通CSVは型検証済みの波長・counts。処理CSVと取得別JSONには生データとBGを対応付けて残す。

## 保存の確定と障害

取得ごとにraw CSV、処理CSV、取得別JSON、points.csvを保存してから保存完了イベントを記録する。取得別JSONと開始イベントには、換算した`power_w`に加えて、メーターが返した`native_value`/`native_unit`、`converted_w`、波長読出し、時刻、ハードウェア読出しを`power_observation`として残す。これは元の単位値を失わず、W換算の再現性を確認するためである。配列・points.csvはflushとsyncを行う。settings.jsonは開始時の設定を保持する。解析確認段階だけPLピーク・積分区間・励起波長の判定条件を変更でき、accepted_settings.jsonとanalysis.jsonへ確定条件を記録する。露光・走査・パワー条件は変更できない。再読込はaccepted_settings.jsonを優先する。ファイルが保存できなければ次の取得へ進まない。既存ファイルへの取得再実行は行わない。

LightField設定スナップショットは、BGと厳密照合する露光、合成フレーム、中心波長、グレーティング、online BG補正に加え、順序を保持したROI（X/Y binningを含む）、ADC gain/speed/quality/bit depth、readout control mode、文書化済みonline correctionを`background_settings`として保存する。実験が明示的にunsupportedと返す設定はその状態を保存するが、SDKメンバー不明または読出し不能は一致とは扱わずBG照合を失敗させる。温度setpointは安定したBG照合条件として保存し、変動する読出し値/statusは別の観測としてBG同一性の条件にしない。生SPEと生配列は、照合失敗時も拒否前に保存する。

JSONは同じフォルダーに一時ファイルを書いて同期し、1回の置換で更新する。旧runの `*.previous.json` は結果を開く際のサンプル一覧から除外する。終了時に `points.csv` とサンプルメタデータの件数・対応を照合し、不一致の場合は `analysis.run.json` の `hash_verification.status` を `incomplete` として理由を `error` に記録する。

再読込は表示用で、途中からの自動再開は未実装。中断ファイルを上書きせず、新規runを作る。

## ライブ表示の範囲

- スペクトルは露光途中の推測値ではなく、取得・保存完了ごとに更新する。
- Heatmapは位置ごとの繰り返しを平均し、励起波長順で並べる。同じ励起波長に量子化された複数位置は表示時だけ取得数で重みを付けて平均し、ゼロ幅の行を作らない。横軸は発光波長／エネルギー。非一様なビンの辺を座標変換して描く。描画時は物理座標を保った行ごとのGPU画像を使い、eV軸では表示用の等間隔座標へ最近傍で再配置する（最大4096横画素）。元データや解析値は変更しない。色はInfernoの最小→最大スケール。負値も処理・表示から除外しない。配色の根拠は[Matplotlibの順序尺度向けcolormap分類](https://matplotlib.org/stable/users/explain/colors/colormaps.html)。
- 監視は通常CONEX約0.4秒、パワー約0.5秒＋機器応答時間。Remote JSONは別接続で移動中も監視・停止できる。旧TCPサーバーが移動中はGETを処理できないため、その間はSTALE表示となる。
- GUIのメモリ上限は800万スペクトルビン、走査上限は2万取得。無限の取得を無制限に保持しない。

## 実機導入時の未検証点

LightField SDK版、カメラ・分光器、CSV列名と単一ROI/frame、SPE保存／エクスポート完了、SDK Stop、CONEXサーバーの到達判定、パワーセンサー単位と校正を対象環境で確認する。テストは実機を接続・移動しない。

## 位置と励起波長の関係・命名

位置ごとに繰り返しを平均したCONEX実位置と励起波長nmから、OLSの傾き・切片・R²を表示する。同じ位置の繰り返し数で回帰の重みを増やさない。2点未満・位置の分散ゼロでは回帰しない。eV表示では波長回帰をエネルギーへ変換して表示する。

生SPE・CSVと処理CSV・JSONは `Y_18.6mm_40uW_p00000_r000` のような共通ベース名を使う。位置6桁、パワーµW4桁まで表示し末尾ゼロを省略する。point/repeat番号は丸めによる衝突を防ぐ。全精度の位置・パワーと対応する励起波長はJSONに残る。解析確定前のpreviewで停止しても、raw CSVとmetadata/preview.jsonを保持する。

Remote Stopの完了待ち中は再接続・次の移動を開始しない。Stopが失敗・タイムアウトした場合は、そのアプリセッションの新規接続・移動を禁止する。遅延Stopの残留がないようリモートサービスと実機を確認・再起動した後にアプリを開き直す。自動シャッターを次runで切断する場合も、閉状態の読戻しを先に要求し、確認できなければ切断・次runへ進まない。

## v0.2：取得時の保証

各取得では露光前にパワーを読みます。`power.wavelength_mode` は `fixed` または `position_calibration`。後者は実位置を事前校正から補間し、センサー波長を設定・読戻ししてから読みます。`wavelength_tolerance_nm` は読戻しの丸めと、取得後の励起ピークとの許容差です。実際のセンサー波長は `power_sensor_wavelength_nm` に保存します。露光中の平均パワーではありません。

LightFieldのベンダーBG補正は無効にし読戻します。取得結果はraw CSVと `metadata/acquisition_<point>_<repeat>.json` を先に確定してから、設定・BGの照合と解析を実施します。後段で失敗してもこの生データは残ります。SPEはLightFieldが出力したファイルだけを保存し、Demoでは生成しません。

Stopの受付と停止完了を区別します。ブリッジの `ensure_idle` はLightFieldの `IsReadyToRun` と自動MFF遮光を確認します。kohdalab-shutterはRust側で独立してCloseと整定状態を待ち、結果を停止・復旧判定に含めます。未確認の停止はエラーとして保持し、次の測定を開始しません。

## v0.2.1の異常復帰と終了

SDK失敗・応答期限切れは、失敗通知だけで終えずStopと待機状態を確認します。未確認の場合は復帰画面を表示し、次のStart・Move・Applyを拒否します。失敗した接続の制御ハンドルも保持し、停止待ちを再接続で消しません。終了時にはStopだけでなくSDKのshutdown・Disposeを要求します。

配布物内の `scripts/verify_run.py` は、CSV・JSONの点番号、実位置、パワー、取得時刻順、BG差分、エネルギー換算、正規化、完了点数を照合します。実機SPEには非ゼロサイズを要求します。SPEの画素内容・物理校正の正しさは検査しません。
